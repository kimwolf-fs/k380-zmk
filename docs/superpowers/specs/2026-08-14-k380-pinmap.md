# K380 Pinmap

**状态：** 已批准，作为 board revision A 的基线

**用途：** 为 K380 电气信号分配提供唯一且可版本化的来源。硬件 revision 的变化
只修改本文件和相应的 pinmap DTSI 文件，不修改扫描器源码。

## Revision A 元数据

| 属性 | 值 |
| --- | --- |
| Board | K380 |
| SoC | nRF52840-QIAA |
| 矩阵 | 8 行 x 15 列 |
| 二极管 | 无 |
| 扫描方向 | row2col |
| 行模式 | 高电平有效、开源输出 |
| 列模式 | 高电平有效、下拉输入 |
| Pinmap 源文件 | `boards/k380/k380/k380-pins-rev-a.dtsi` |

## Pinmap DTSI 约定

带 revision 的 DTSI 文件定义所有包含 K380 GPIO 分配的节点和属性：

- 带 label 的 K380 kscan node，以及 `row-gpios` 和 `col-gpios`
- 可选 LED
- 可选电池检测
- 可选外部电源控制
- 可选显示屏总线
- 可选编码器 GPIO

board DTS 包含选定 revision 后仅引用其 label。除选定的 pinmap include 外，board
DTS 中不得出现 K380 信号对应的字面量 `&gpio0` 或 `&gpio1` 分配。

扫描器只消费带 label 的 kscan node 提供的 `row-gpios` 和 `col-gpios` 数组，
不依赖具体 revision 或 nRF52840 GPIO 编号。

## 扩展硬件

新增硬件必须使用新的 pinmap revision。示例：

| 变更 | Pinmap 必需动作 | 驱动影响 |
| --- | --- | --- |
| 矩阵引脚改线 | 新增 revision，仅替换信号 GPIO | 无 |
| 状态 LED | 新增语义化 LED node 和 GPIO | 无 |
| RGB 或背光 | 新增 LED 控制、数据和电源信号 | 不影响鬼键过滤 |
| 电池检测 | 新增 ADC 输入和分压信息 | 无 |
| OLED 或显示屏 | 新增 I2C/SPI 总线和控制信号 | 无 |
| 编码器 | 新增 A/B/按键开关信号 | 无 |
| 电源开关 | 新增 enable 和 wakeup 信号 | 无 |

每个 revision 必须：

1. 保留完整的矩阵章节。
2. 说明此前 revision 的固件是否仍具有电气兼容性。
3. 保证同一激活配置中没有 GPIO 被重复分配。
4. 成功构建对应的 board target。
5. 通过完整矩阵逐键测试和外设专用硬件测试。

## Revision 选择

Revision A 仅适用于引脚连接与本文完全一致的硬件。后续 revision 通过 board
variant 或显式选择的 DTSI include 启用。固件产物名称必须包含 board revision，
避免将某一 revision 的 UF2 镜像错误刷入另一 revision 的硬件。
