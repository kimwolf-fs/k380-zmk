# K380 Pinmap

**Status:** Approved baseline for board revision A

**Purpose:** Provide one revisioned source of truth for K380 electrical signal
assignments. Hardware revisions change this document and the corresponding
pinmap DTSI file, not scanner source code.

## Pinmap DTSI Contract

The revisioned DTSI file defines all nodes and properties that contain K380
GPIO assignments:

- The labelled K380 kscan node with `row-gpios` and `col-gpios`
- Optional LEDs
- Optional battery sensing
- Optional external power control
- Optional display buses
- Optional encoder GPIOs

The board DTS includes the selected revision and references its labels. It
must not contain literal `&gpio0` or `&gpio1` assignments for K380 signals
outside the selected pinmap include.

The scanner consumes only the `row-gpios` and `col-gpios` arrays exposed by
the labelled kscan node. It has no dependency on this revision or on
nRF52840 GPIO numbers.

## Extending Hardware

New hardware uses a new pinmap revision. Examples include:

| Change | Required pinmap action | Driver impact |
| --- | --- | --- |
| Matrix pin reroute | Add a new revision and replace only the signal GPIOs | None |
| Status LED | Add a semantic LED node and its GPIO | None |
| RGB or backlight | Add LED control and data/power signals | None to ghost filter |
| Battery monitor | Add the ADC input and divider metadata | None |
| OLED or display | Add I2C/SPI bus and control signals | None |
| Encoder | Add A/B/switch signals | None |
| Power switch | Add enable and wakeup signals | None |

Every revision must:

1. Retain a complete matrix section.
2. State whether prior revision firmware remains electrically compatible.
3. Reserve no GPIO twice within the same active configuration.
4. Build the corresponding board target.
5. Pass a full matrix walk and peripheral-specific hardware test.

## Revision Selection

Revision A is the default only for hardware wired exactly as listed above.
A later revision is selected by a board variant or an explicitly selected DTSI
include. Firmware artifacts must include the board revision in their release
name so a UF2 image cannot be confused with another hardware revision.
